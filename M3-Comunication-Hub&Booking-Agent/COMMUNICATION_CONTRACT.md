# RailSense AI — Member C Communication Contract

> **Phase 1 document.** This file captures the agreed API contracts and
> architectural rules for the Agent Communication Hub and Booking Agent.
> It is updated as each phase adds new behaviour.

---

## 1. Message Flow

All inter-agent communication is **hub-mediated**. No agent calls another
agent directly.

```
Sender Agent
    │
    │  POST /messages          (AgentMessage envelope)
    ▼
Agent Communication Hub        ← Member C service, port 8002
    │
    │  POST /internal/messages (same AgentMessage envelope, forwarded)
    ▼
Receiver Agent
```

### Member C primary flow

```
Passenger Agent  (port 8001)
    │
    │  intent: booking_request | cancel_booking
    ▼
Agent Communication Hub  (port 8002)
    │
    ▼
Booking & Reservation Agent  (port 8003)
```

---

## 2. AgentMessage Envelope

Every message sent through the hub **must** conform to this schema
(`member-c/shared/schemas.py → AgentMessage`).

| Field            | Type               | Required | Notes                                              |
|------------------|--------------------|----------|----------------------------------------------------|
| `message_id`     | `str`              | Yes      | Unique identifier, e.g. `"MSG-2001"`               |
| `sender_agent`   | `str`              | Yes      | Logical name, e.g. `"passenger-agent"`             |
| `receiver_agent` | `str`              | Yes      | Logical name, e.g. `"booking-agent"`               |
| `intent`         | `MemberCIntent`    | Yes      | See section 3 for allowed values                   |
| `payload`        | `dict[str, Any]`   | Yes      | Intent-specific body (see section 4)               |
| `auth_token`     | `str`              | Yes      | Raw bearer token — not verified in Phase 1         |
| `timestamp`      | `datetime`         | Yes      | ISO-8601, timezone-aware recommended               |

### Validation rules (enforced by Pydantic)

- All `str` fields: `min_length=1` (whitespace-stripped).
- `intent`: must match a value in `MemberCIntent` enum exactly.
- `auth_token`: presence enforced; JWT structure verified in Phase 2.

## 4. Payload Contracts

### 4.1 `booking_request` payload

Maps to `BookingRequest` (`booking-agent/schemas/booking.py`).

```json
{
  "from_station":    "Colombo",
  "to_station":      "Kandy",
  "travel_date":     "2026-12-03",
  "train_id":        "PM-4082",
  "seat_class":      "Second Class",
  "passenger_count": 1
}
```

| Field             | Type   | Constraints                    |
|-------------------|--------|--------------------------------|
| `from_station`    | string | non-empty                      |
| `to_station`      | string | non-empty                      |
| `travel_date`     | date   | today or future (YYYY-MM-DD)   |
| `train_id`        | string | non-empty                      |
| `seat_class`      | string | non-empty                      |
| `passenger_count` | int    | 1 to 10 inclusive              |

**All fields are mandatory.**
`BookingRequest` represents the final submission after the passenger has
completed every required field on the booking page.
Missing fields must be resolved before the message is dispatched — the
booking agent must not invent or default passenger data.

### 4.2 `cancel_booking` payload

Maps to `CancellationRequest` (`booking-agent/schemas/cancellation.py`).

```json
{
  "booking_reference": "RS-84521",
  "reason":            "I accidentally booked twice"
}
```

| Field               | Type   | Constraints           |
|---------------------|--------|-----------------------|
| `booking_reference` | string | non-empty             |
| `reason`            | string | 3 to 1 000 characters |

**`reason_category` is intentionally absent.**
It will be generated by the NLP component in a later phase and must not be
supplied by the passenger.

## 5. Agent Registry

Defined in `member-c/agent-hub/registry.py`.

| Logical name        | Default URL                 | Owner        |
|---------------------|-----------------------------|--------------|
| `passenger-agent`   | `http://localhost:8001`     | Other member |
| `booking-agent`     | `http://localhost:8003`     | Member C     |
| `security-agent`    | `http://localhost:8004`     | Other member |
| `operations-agent`  | `http://localhost:8005`     | Other member |
| `maintenance-agent` | `http://localhost:8006`     | Other member |

All URLs are overridden via environment variables (see `agent-hub/.env.example`).

### Registry API (Phase 1 — lookup only, no HTTP calls)

```python
from registry import get_agent_url, get_agent_entry, list_agents, AgentNotFoundError

url   = get_agent_url("booking-agent")    # "http://localhost:8003"
entry = get_agent_entry("booking-agent")  # AgentEntry(name=..., base_url=..., description=...)
all_  = list_agents()                     # sorted list of all AgentEntry objects

# Unknown name raises AgentNotFoundError (subclass of KeyError)
url   = get_agent_url("unknown-agent")    # raises AgentNotFoundError
```

## 6. Architectural Rules

These rules govern what the hub **is** and **is not** responsible for.

### The Hub IS responsible for (Phase 2+)

```
Receive  ->  Validate  ->  Authenticate  ->  Audit  ->  Route
```

1. **Receive** — Accept `AgentMessage` over HTTP POST `/messages`.
2. **Validate** — Pydantic schema validation (active in Phase 1).
3. **Authenticate** — Verify `auth_token` JWT with the Security Agent.
4. **Audit** — Write a record to `audit_logs` before and after routing.
5. **Route** — Forward the message to the correct downstream agent via
   `registry.get_agent_url(message.receiver_agent)`.

### The Hub is NOT responsible for

| Responsibility              | Correct owner              |
|-----------------------------|----------------------------|
| Booking creation / updates  | booking-agent              |
| Seat availability checks    | booking-agent + database   |
| Fare calculation            | booking-agent + database   |
| Cancellation decisions      | Admin (human-in-the-loop)  |
| NLP / intent classification | NLP component (later)      |
| RAG / document retrieval    | RAG component (later)      |
| LLM responses / decisions   | Never for booking facts     |

### Hard rules

**Booking facts (availability, fare) must come from deterministic
backend/database logic — never from an LLM.**
An LLM may assist with conversation, but the booking agent's database
is the single source of truth for seat inventory and pricing.

**Cancellation final approval must remain human-in-the-loop.**
Even when an AI summary and eligibility recommendation are generated,
an admin must make the final approve/reject decision.

**No agent calls another agent directly.**
All traffic flows through the hub so that audit, authentication, and
routing logic is applied consistently.

## 7. HTTP Endpoints Reference

### Agent Communication Hub (`localhost:8002`)

| Method | Path        | Phase | Description                                   |
|--------|-------------|-------|-----------------------------------------------|
| GET    | `/health`   | 1     | Liveness probe                                |
| POST   | `/messages` | 1     | Receive and validate AgentMessage (ack only)  |
| POST   | `/messages` | 2     | Full: validate, authenticate, audit, route    |
| GET    | `/docs`     | 1     | Swagger UI                                    |

### Booking & Reservation Agent (`localhost:8003`)

| Method | Path                              | Phase | Description                      |
|--------|-----------------------------------|-------|----------------------------------|
| GET    | `/health`                         | 1     | Liveness probe                   |
| POST   | `/internal/messages`              | 1     | Receive AgentMessage (ack only)  |
| POST   | `/internal/messages`              | 2     | Full intent dispatch + DB write  |
| GET    | `/bookings/{booking_reference}`   | 2     | Retrieve booking record          |
| GET    | `/cancellations`                  | 2     | List cancellation requests       |
| GET    | `/cancellations/{case_reference}` | 2     | Retrieve cancellation request    |
| GET    | `/docs`                           | 1     | Swagger UI                       |
